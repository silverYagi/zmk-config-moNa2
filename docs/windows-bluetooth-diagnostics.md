# Windows Bluetooth接続の診断版

WindowsでmoNa2が見つかるものの、6桁のパスキーが一度も表示されず「もう一度デバイスを接続してください」で失敗する状況を調べます。
左右は右側のUSB接続で両方入力でき、PMW3360も動作確認済みです。
この版は解決済みのファームウェアではなく、失敗理由を取得する一時的な診断版です。

## 変更内容

- パスキー版にログ設定、独立したUSBシリアル、Bluetooth通知コールバックを追加します。
- 接続時のHCIステータス、切断時のHCI理由コード、認証結果、ペアリング失敗理由を記録します。
- 追加コールバックは通知専用です。認証を許可・拒否する処理は変更しません。
- ZMKの通常デバッグ出力は抑え、追加コールバックにはキーコード・パスキー・暗号鍵を出しません。
- PMW3360、ピン配置、6レイヤー、DYA Studio、2M PHY無効化を引き継ぎます。

## 書き込みと採取

1. DYAでの変更後は10秒以上待ちます。
2. 右のリセットを素早く2回押し、`mona2-right-keyball39-dya-pmw3360-bt-diagnostics.uf2`を書き込みます。
3. 左は現在のDYA対応版を使用します。`settings_reset`は書き込みません。
4. 左右の電源をONにし、右をUSB接続したままにします。
5. DYAでWindows用の空きプロファイルを選び、保存を待ちます。既存のWindows用を使う場合はそのプロファイルだけをクリアします。
6. DYAのUSB接続を切断し、右USBは挿したまま、USBシリアルのログを開きます。USBにはDYA用とログ用の2つのCOMポートが現れます。
7. Bluetooth管理キー＋Wの位置でBluetooth出力を選択します。
8. WindowsでmoNa2への接続を一度試し、直後までのログを保存します。USBケーブルは抜きません。
9. 終了後、Bluetooth管理キー＋Qの位置でUSB出力に戻せます。

ログ表示は115200bps、8ビット、パリティなし、ストップビット1、フロー制御なしです。シリアルのDTRを有効にしてください。
接続前からログを開いておく必要があります。採取後に開いても、過去の失敗は取得できません。
COM番号は環境で変わります。番号を固定せず、接続時に増えたポートを調べます。
DYAのRPC用ポートには読めるログは出ません。DYAとの同時使用を避け、ログ用ポートを選択してください。

## 読み方

`mona2_ble_diagnostics`が追加したログです。`role=0`は左右間の中央接続、`role=1`はWindowsなどホストからの接続を示します。

- `connected ... status=0x00`: 接続成立。ペアリング成功を意味しません。
- `security ... err=0`: その接続の認証レベル変更が成功。
- `pairing_failed ... reason=N`: Zephyrの`bt_security_err`列挙値。HCIコードとは区別します。
- `disconnected ... reason=0xNN`: Bluetooth HCI切断理由。
- `Rejecting pairing request to taken profile`: 選択中プロファイルが登録済みで拒否されたことを示します。
- 接続操作後もホスト側のログが一切ない場合は、キーボードに接続が届いていない可能性と、ログ用COMの選択ミスを分けて確認します。

## 採取後

ログ出力は消費電力と動作タイミングに影響するため、採取後は同梱の`mona2-right-keyball39-dya-pmw3360-passkey.uf2`へ戻してください。
いずれもパスキー方式のため、この2つの間では認証方式を変更しません。
設定リセットは不要です。

[ZMK公式のUSBログ採取方法](https://zmk.dev/docs/development/usb-logging)
