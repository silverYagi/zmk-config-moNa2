# 保存済みキーが未割当になる問題への互換修正

旧`822d568`版は動作IDを`behavior/local_id/<番号>`の保存テーブルで管理していました。
診断機能追加版`9e8818a`ではCRC16方式に切り替えたため、旧テーブル方式で保存されたキーマップが、そのままでは解決できませんでした。
既定配列6層×42キーは正しくても、保存済み設定が上書きすると未割当になります。

さらにDYA Studio側の公式キーマップRPCのエラー番号解釈にずれがあります。
使用中のprotoでは応答2が`INVALID_BEHAVIOR`ですが、DYAの`useKeymap.ts`はこれを`INVALID_KEY_POSITION`として表示します。
したがって`Invalid key position: 41`だけで、42番目のキーが範囲外だとは判断できません。

## 修正内容

右側に、保存済みの旧`behavior/local_id`テーブルを読む互換ハンドラーを追加します。
現行CRC16で解決できない動作IDのみ、旧テーブルの動作名から現在の動作へ読み替えます。
現行CRC16の動作IDが存在する場合は、そちらを優先します。
存在しなくなった動作を別の動作に置き換えたり、設定を消去したりしません。
読み取りだけの処理で、起動時のフラッシュ書き換えはありません。
キーマップの設定が旧テーブルより先に読み込まれても、ZMKの設定commit時の再検索で解決します。

## 書き込み

右側だけを修正版の`mona2-right-pmw3360-dya-features.uf2`に更新します。
左は診断対応版`9e8818a`の`mona2-left-dya-features.uf2`を引き続き使います。
キーボードを再起動した後、DYAを切断してページを再読み込みし、USBで接続し直してください。
以前の動作IDをブラウザー内に残したまま編集しないためです。

設定リセットやキーマップ全消去は不要です。
ただし既に未割当の状態を保存したり、旧テーブルを全消去した場合、その情報は読み替えだけでは復旧できません。
その場合の復旧元として、ファームウェア内の既定値と添付の`mona2-2026-10-19.keymap`は維持しています。

## 検証

同じ互換ソースをホストGCCでリンクし、旧ID・現行CRC16・読み込み順・未知ID・重複・容量上限・不正入力を検証します。
ファームウェア側でも互換コードのコンパイルと`--wrap`リンクを確認します。
実機で保存済みキーの復旧とDYA編集ができるかは、書き込み後の確認が必要です。
